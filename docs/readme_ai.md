## AI-функция

ИИ помогает бизнесу превратить сырой черновик в полную карточку задачи. Он не придумывает факты и не считает рейтинг: он только раскладывает слова пользователя по полям и задаёт уточняющие вопросы. Код отвечает за всё, что влияет на решения: проверяет цитаты, выбирает вопросы и их баллы, считает рейтинг.

### Две функции

| Функция | Вход | Выход |
|---|---|---|
| `analyze_draft(draft_text, industry)` | черновик и отрасль | карточка из уже известных фактов, цитаты-источники, отброшенные поля, 3–5 вопросов |
| `build_card(draft_text, industry, questions, answers, prev_card)` | черновик, вопросы, ответы, текущая карточка | обновлённая карточка, цитаты, отброшенные поля |

Обе возвращают `ai_mode`: кто реально ответил (`openai`, `nvidia` или `stub`). Интерфейс показывает это тегом «ИИ: …».

### Промпты (`backend/app/ai/prompts.py`)

Системный промпт описывает 10 полей карточки с весами из формулы рейтинга. Так модель спрашивает сначала о самом весомом. Жёсткие правила промпта:

1. Никаких выдуманных фактов: поле заполняется, только если пользователь прямо об этом написал.
2. `evidence` — дословная цитата из текста пользователя. Нет цитаты — `value = null`.
3. Никаких выводов: из «Мы сеть кофеен» не следует ни «пользователи — клиенты кофеен», ни данные.
4. `context` — это компания и проблема, `need` — только желаемое изменение.
5. Вопросы только по пустым полям, в порядке важности. Каждый вопрос называет детали черновика и подсказывает варианты ответа, до 25 слов. Если нет контакта, последний вопрос про контакт.
6. Ответ — только JSON, на русском.

Для сборки карточки промпт дополнительно просит раскладывать ответ по нескольким полям, если в нём есть сведения для других полей. Например, «anna@example.com, созвон раз в неделю» разбирается на контакт и формат.

### Формат ответа модели

```json
{"fields": {"context": {"value": "Мы небольшая сеть кофеен в Алматы. Продажи в будние дни падают",
                        "evidence": "Мы небольшая сеть кофеен в Алматы. Продажи в будние дни падают"},
            "need":    {"value": "Хотим понять почему и что делать",
                        "evidence": "хотим понять почему и что делать"}},
 "questions": [{"field": "data",
                "text": "Какие данные о продажах кофеен в будние дни вы можете дать команде: выгрузку чеков, отчёты по дням, за какой период?",
                "why": "чтобы понять причины падения продаж"}]}
```

`id` и `points` вопросов модель не присылает, их проставляет код. `points` — сумма баллов непройденных проверок рейтинга по этому полю.

### Защита от выдуманных данных (`backend/app/ai/guard.py`)

Поле из ответа модели принимается, только если выполнены оба условия:

- **цитата подтверждена:** после нормализации (нижний регистр, ё→е, без пунктуации) `evidence` — подстрока текста пользователя, либо ≥ 70% её слов длиной от 4 букв есть в этом тексте;
- **цифры не выдуманы:** все числа в значении есть в тексте пользователя. «Рост на 15%» не пройдёт, если пользователь не называл 15.

Иначе поле остаётся пустым и попадает в `removed` с причиной «нет подтверждения в тексте пользователя». Интерфейс показывает такие поля как «ИИ не стал заполнять». Название (`title`) может быть кратким пересказом без цитаты, до 100 символов. Под каждым полем от ИИ в интерфейсе видна его цитата: «Из вашего текста: «…»».

При сборке карточки прежнее значение сохраняется, если новое не прошло guard. Ответ, который модель не разложила, кладётся дословно в поле своего вопроса. Слова пользователя не теряются.

### Вопросы: всегда 3–5

Вопросы модели по уже закрытым полям отбрасываются. Если вопросов меньше 5, код добивает их шаблонами по самым весомым пробелам рейтинга. Если в карточке нет контакта, вопрос о нём задаётся всегда. У почти полного черновика шаблонные вопросы, которые не дают баллов, честно помечены: «Поле уже заполнено, баллов не добавит».

### Некорректный ответ и сбои (`backend/app/ai/client.py`)

Цепочка провайдеров: **OpenAI → NVIDIA Build (OpenAI-совместимый API) → локальная заглушка**. Провайдер без ключа пропускается.

На каждом провайдере:

1. Запрос с таймаутом 20 с, `temperature=0`. OpenAI работает в режиме JSON (`response_format=json_object`). При сетевой ошибке или ответе 5xx SDK делает один автоматический повтор.
2. Ответ проходит `json.loads` и валидацию Pydantic. Строки `"null"` считаются пустыми значениями, обёртка ```` ```json ```` снимается.
3. Если ответ не разобрался, делается **один повтор** с сообщением об ошибке и напоминанием о схеме.
4. Если и повтор не удался, или API вернул ошибку (например, 403), запрос уходит к следующему провайдеру. Все сбои пишутся в `logging.warning`.

Если не ответил никто, работает локальная заглушка. Сбой ИИ никогда не даёт ошибку 500.

### Режим `AI_MODE=stub`

`AI_MODE=stub` в `backend/.env` сразу включает локальную заглушку (`backend/app/ai/stub.py`), ключи не нужны. Заглушка тоже не выдумывает. `context` — это весь черновик. Дословные фрагменты по маркерам раскладываются по полям: «хотим/нужно…» → потребность, «выгрузка, CSV, таблица…» → данные, «срок, NDA, стек…» → ограничения, email, телефон и @ник → контакт. Вопросы берутся из шаблонов по самым весомым пробелам, каждый ответ идёт в поле своего вопроса. Демо-сценарий в этом режиме даёт те же цифры: 10 → 65 → 90.

### Качество

`python -m scripts.ai_check` прогоняет анализ и сборку на 5 черновиках из seed с реальным ключом и проверяет правила:
- 3–5 вопросов без повторов;
- вопросы опираются на детали черновика;
- у каждого поля есть цитата из ввода;
- цифр не из ввода нет;
- ни один ответ не потерян.

Последний прогон: нарушений 0, откатов на заглушку 0, анализ 3–5 с, сборка 2–5 с. Примеры «вход → выход» и список правок промпта по итогам проверки — в [`docs/ai_examples.md`](docs/ai_examples.md).
