# Проверка A3

Последующая проверка актуального backend, подключения `.env` и требований кейса: [CASE_AUDIT.md](CASE_AUDIT.md). На коммите `7299ab0` прежняя заглушка маршрута рекомендаций заменена работающим движком.

Проверено 23 сентября 2026: 6 frontend-тестов, production-сборка, 86 backend-тестов и smoke-прогон 16 API-маршрутов. UI проверен в браузере с реальным FastAPI, `AI_MODE=stub` и отдельной SQLite БД. Основная БД не изменялась в этом прогоне.

## Что проверено в UI

- Каталог → задача; таблица «Мои задачи» → задача; ссылки обратно в каталог.
- Все 10 полей, источники evidence, подтверждённый рейтинг, история и глобальное место.
- Пример из API → 5 вопросов → карточка → подтверждение → публикация.
- Сохранённый конструктор `/tasks/new?task=ID` восстанавливает серверный этап после обновления страницы; незавершённую задачу можно продолжить со страницы задачи.
- Редактирование опубликованной задачи: прогноз 90 не меняет сохранённые 65/#4; подтверждение меняет их на 90/#2 и показывает историю, анимацию и уведомление.
- Валидация названия, пустого отклика и URL; ошибка сохранения не очищает введённые данные.
- Отклик DataCats на опубликованную задачу draft с предупреждением; неопубликованная задача отклики не принимает.
- Отмена Popconfirm не меняет решение; одновременно выбраны две команды; отклонение одной не меняет другую.
- Подтверждение этапа выбранной команде: +10 баллов, счётчик этапов и баллы в шапке обновляются.
- Пустые отклики; отсутствующая задача (404) и ссылка возврата; недоступный API и успешная повторная загрузка после его запуска.
- В обычном сквозном сценарии ошибок JS в консоли не было. В негативных проверках ожидаемо получены ошибки HTTP при выключенном API и 404.

## Повторный запуск проверок

Из `frontend/`:

```powershell
npm.cmd test
npm.cmd run build
```

Для тестов используется Node.js 22.6+ с поддержкой `--experimental-strip-types` (проверено на Node.js 24).

API-smoke создаёт тестовые задачи и отклики, меняет решения и баллы. Запускать **только на отдельной тестовой БД**, не на основной БД демонстрации. Поднять второй backend на порту 8001 с отдельным `DATABASE_URL` и `AI_MODE=stub`, затем из `frontend/`:

```powershell
$env:TASKREADY_TEST_API = 'http://localhost:8001'
npm.cmd run test:api
```

Прогон проверяет seed-справочники, глобальные позиции под фильтрами, жизненный цикл задачи, отсутствие сохранения при preview, 400/404/422, отклики, независимые решения, этап и баллы, доступность рекомендаций.

## Ограничения, которые нельзя исправить только во frontend

- На коммите backend `6dc8ee8` функция `list_recommendations` в `backend/app/routers/teams.py` возвращает `[]`, хотя движок `recommend()` уже есть. Фронт вызывает маршрут и показывает пустое состояние. Лиду нужно подключить движок к маршруту; непустые рекомендации нужно перепроверить после подключения. Сам каталог при этом работает полностью и не фильтруется рекомендациями.
- Прямые вызовы реальных OpenAI/NVIDIA с платными ключами в этом прогоне не выполнялись. UI использует фактический `ai_mode` из API.
- Ссылки прототипов seed вида `example.com/...` — демонстрационные данные, не существующие разработки команд. UI открывает только корректные HTTP(S)-ссылки в новой вкладке с `noopener noreferrer`.
- У Vite остаётся предупреждение о размере JS-бандла; сборка завершается успешно.
